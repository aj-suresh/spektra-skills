# The context pack

What to pull from the user's product context before writing any copy. The source might be a product
skill, a file such as `.agents/product-marketing.md`, a URL, or a brief the user pasted. Its headings
will differ from this table, so look for each item by meaning.

| Need | Typically found under | Used for |
|---|---|---|
| Job to be done, with an ID if it has one | Jobs, use cases, problems solved | The pain and outcome each ad group speaks to |
| Persona and buying centre | Buying committee, ICP, audience | Who the copy talks to |
| Triggers and buying signals | Triggers, timing, events | Timing hooks (renewal, deadline, launch) |
| Message pillars and headline options | Messaging, positioning | Angles and phrasing that already tested well |
| Proof points marked safe to use | Proof points, customers, certifications | Headlines and descriptions that can carry a claim |
| Claim guardrails with risk grades | Claim guardrails, legal notes, off-limits claims | The `blocked_claims` and `hedged_claims` lists in the payload |
| Named customers | Proof points, case studies | The `customers` list, so each use is flagged for sign-off |
| Competitive frame | Competitors, alternatives, battlecards | Positioning per rival, and what not to fight on |
| Prior creative | Past ads, channel notes | Calibration only. Re-check every line against the policy rules before reusing it |
| Qualifying test and disqualifiers | At a glance, ICP | Ad groups that should not run at all |

If an item is missing, say so in the brief rather than filling the gap from memory. A missing guardrail
table is the one to raise first: without it you can't tell which claims are safe, so keep the copy to
facts the landing page states plainly.
